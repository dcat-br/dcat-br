Resumo

O DCAT-BR é um perfil de aplicação brasileiro do vocabulário Data Catalog Vocabulary (DCAT), utilizado para descrever catálogos de dados e seus recursos (conjuntos de dados e serviços de dados), desenvolvido primariamente para uso pelos portais de dados do setor público brasileiro e entidades vinculadas. A especificação define classes, propriedades e boas práticas para promover uma descrição padrão dos metadados, corroborando com a interoperabilidade semântica entre catálogos nacionais e internacionais, bem como para apoiar iniciativas de open data e linked data.

Status deste documento

Esta é a primeira versão oficial do vocabulário DCAT-BR, elaborada pelo Grupo de Trabalho DCAT-BR. Futuras revisões seguirão o processo de governança de dados nacional, com participaçãode órgãos federais, estaduais, municipais e entidades vinculadas.

Comentários e propostas de alteração devem ser enviados por meio do repositório público indicado na seção de governança e manutenção.

Introdução

A disseminação de dados governamentais em múltiplas plataformas exige um vocabulário comum para descrição de metadados, de forma a viabilizar a descoberta, combinação e reuso de conjuntos de dados em escala nacional. O vocabulário DCAT [[VOCAB-DCAT]], criado pelo World Wide Web Consortium (W3C), fornece um modelo RDF para a descrição de catálogos de dados na Web, permitindo a interoperabilidade entre diferentes portais.

O DCAT-BR 1.0 especializa o Data Catalog Vocabulary (DCAT) versão 3 [[VOCAB-DCAT-3]], alinhando-o às necessidades do contexto brasileiro. Ele estabelece um conjunto de classes, propriedades obrigatórias e opcionais, bem como vocabulários controlados, para descrever conjuntos de dados do setor público de forma padronizada. O uso de agregadores de conteúdo como o Portal Brasileiro de Dados Abertos e Catálogo Nacional de Dados, entre outros, garante o acesso através do uso do protocolo de forma agnóstica.

O vocabulário também é projetado para ser utilizado por outros atores, como empresas, academia e organizações da sociedade civil, desde que observadas as regras de adesão ao ecossistema DCAT-BR.

Objetivos

  • Fornecer uma especificação comum para descrever os catálogos de dados da administração pública brasileira;
  • Garantir conformidade ao DCAT e interoperar com os demais perfis de aplicação internacionais;
  • Apoiar a catalogação federada de conjuntos de dados e distribuições em múltiplas plataformas;
  • Promover a descoberta, reuso e integração de dados governamentais por pessoas e sistemas.

Benefícios de uso

  • Consistência na descrição: os metadados seguem padrões uniformes, garantindo coerência entre portais de dados, agregadores de conteúdo e catálogos setoriais;
  • Fomento do reuso dos dados: os órgãos públicos, ao compartilhar informações sobre seus conjuntos de dados, facilitam a criação de novas soluções, serviços, políticas públicas e outras iniciativas por parte da sociedade civil, academia e setor privado;
  • Redução da redundância: a aderência ao DCAT-BR proporciona maior visibilidade e organização dos conjuntos de dados, evitando a duplicação de esforços na sua descrição e publicação;
  • Promoção da interoperabilidade: ao adotar um padrão internacional, seguido por vários portais de dados governamentais, os metadados tornam-se compatíveis com os princípios de Open Data e Linked Data.

Conformidade

Assim como as seções marcadas como não normativas, todas as diretrizes de autoria, diagramas, exemplos e notas nesta especificação são não normativas. Todo o restante é normativo.

Requisitos do provedor de dados

Um catálogo, portal ou serviço declara conformidade com o DCAT-BR quando:

  • para cada conjunto de dados descrito como dcat:Dataset, são fornecidos todos os metadados marcados como obrigatórios nesta especificação;
  • as propriedades e classes RDF utilizadas pertencem aos namespaces (espaços de nomes) indicados na seção de prefixos e namespaces;
  • quaisquer extensões locais são compatíveis com o modelo RDF e não contradizem as definições desta especificação ou do DCAT v3, de modo a preservar a interoperabilidade semântica;
  • os dados podem ser serializados em formatos RDF padronizados, como Turtle ou RDF/XML.

Requisitos do consumidor de dados

Uma aplicação que recebe metadados declara conformidade com o DCAT-BR quando:

  • é capaz de processar metadados que utilizam as classes e propriedades definidas nesta especificação, bem como as classes e propriedades do DCAT v3;

Legislação nacional

A adoção do DCAT-BR como padrão nacional está apoiada em um conjunto de leis e decretos que tratam de transparência, dados abertos, governo digital, proteção de dados e interoperabilidade no setor público. Essas normas dispõe as condições necessárias para que os conjuntos de dados governamentais sejam organizados, compartilhados e reutilizados de forma padronizada.

Entre os principais instrumentos legais, destacam-se:

  • Lei nº 12.527/2011 - Lei de Acesso à Informação;
  • Decreto nº 8.777/2016 - Política de dados abertos no âmbito da administração pública federal;
  • Decreto nº 10.046/2019 - Governança no compartilhamento de dados no âmbito da administração pública federal e institui o Comitê Central de Governança de Dados;
  • Lei nº 13.708/2018 - Lei Geral de Proteção de Dados (LGPD);
  • Decreto nº 14.129/2021 - Lei de Governo Digital;
  • Decreto nº 12.198/2024 - Estratégia Federal de Governo Digital e a instituição da Infraestrutura Nacional de Dados.

Governança e manutenção

O DCAT-BR é mantido pelo Grupo de Trabalho DCAT-BR. Alterações na especificação são discutidas e comunicadas publicamente, de modo a preservar a interoperabilidade entre implementações e a rede federada de catálogos.

O modelo de contribuição prevê:

  1. Registro de propostas de alteração em repositório público versionado.
  2. Análise técnica pelo Grupo de Trabalho DCAT-BR.
  3. Período de consulta pública, quando apropriado.
  4. Publicação de novas versões, acompanhadas de notas de versão, artefatos RDF e SHACL.

Modelo de informações

Classes principais

O DCAT-BR utiliza e especializa classes do DCAT 3 e de vocabulários relacionados, organizando o modelo em torno dos seguintes tipos de recursos:

Conjunto de Dados (dcat:Dataset)
Uma coleção de dados publicada ou curada por um único agente, disponível para acesso ou download em uma ou mais representações.
Recurso (dcat:Resource)
Recurso publicado ou curado por um único agente. Inclui conjuntos de dados, serviços de dados e outros recursos catalogados.
Distribuição (dcat:Distribution)
Uma representação específica de um conjunto de dados, por exemplo, um arquivo CSV, uma API ou outro formato de acesso.
Período de Tempo (dcterms:PeriodOfTime)
Intervalo de tempo definido por um início e um fim, utilizado para descrever a cobertura temporal de conjuntos de dados.
Local (dcterms:Location)
Região espacial ou lugar nomeado, utilizado para descrever a cobertura geográfica de conjuntos de dados.
Serviço de Dados (dcat:DataService)
Coleção de operações que fornece acesso a um ou mais conjuntos de dados ou funções de processamento de dados.
Verificação de Integridade (spdx:Checksum)
Valor de checksum usado para verificar a integridade do conteúdo de um arquivo ou pacote. Mesmo pequenas alterações no conteúdo do arquivo alterarão seu Checksum. Esta classe permite que os resultados de uma variedade de algoritmos de Checksum e resumo de mensagens criptográficas sejam representados.
Relacionamento (dcat:Relationship)
Classe utilizada para descrever um relacionamento qualificado entre recursos catalogados. Normalmente referenciada por dcat:qualifiedRelation.
Agente (foaf:Agent)
Fornece diversas propriedades para descrever pessoas, organizações ou entidades. Pode ser uma foaf:Organization ou foaf:Person.

Validação RDF

As restrições do DCAT-BR são expressas em SHACL [[shacl]] para permitir a validação de catálogos na troca de dados entre sistemas. O DCAT-BR fornece um conjunto de expressões SHACL organizadas em arquivos separados, cada um contendo um subconjunto específico de restrições. Esses arquivos são projetados para apoiar diferentes configurações típicas de validação, permitindo que os implementadores escolham as expressões mais relevantes para suas necessidades específicas.

Os arquivos de expressões estão disponíveis no repositório oficial do projeto no GitHub.

Glossário

Especificação: documento que define os requisitos e características de um sistema ou componente. Nesse caso, para o DCAT-BR.

Interoperabilidade: capacidade de diversos sistemas e organizações trabalharem em conjunto, de modo a garantir que pessoas, organizações e sistemas computacionais troquem dados. (Decreto 10.046/19)

Interoperabilidade semântica: capacidade de diversos sistemas e organizações trabalharem em conjunto, de modo a garantir que pessoas, organizações e sistemas computacionais troquem dados, com base em um entendimento compartilhado do significado dos dados.

Linked Data: abordagem para publicar e interconectar dados na web usando padrões abertos, como RDF e URIs, para criar uma rede de dados interligados e acessíveis.

Metadados: representam "dados sobre dados", fornecendo os recursos necessários para entender os dados no decorrer do tempo, ou seja, são dados estruturados que fornecem uma descrição concisa a respeito dos dados armazenados e que permitem encontrar, gerenciar, compreender ou preservar informações a respeito dos dados ao longo do tempo. Possuem um papel importante na gestão de dados, pois, a partir deles, as informações são processadas, atualizadas e consultadas. As informações de como os dados foram criados ou derivados, do ambiente em que residem ou residiram, das alterações realizadas, dentre outras, são obtidas de metadados. (Portaria GSI/PR Nº 93, 2021)

Open Data: dados que são disponibilizados de forma aberta e livre para uso, reutilização e distribuição.

Perfil de aplicação: especificação de um vocabulário RDF que define as classes e propriedades a serem utilizadas para descrever recursos de um domínio específico, incluindo restrições e orientações sobre o uso desses termos. O DCAT-BR é um perfil de aplicação do DCAT para o contexto brasileiro.

Recurso: uma entidade que pode ser descrita usando RDF, representada por um URI. No DCAT-BR, recursos são representados pela classe dcat:Distribution, que podem ser conjuntos de dados, serviços de dados, entre outros.

RDF: Resource Description Framework, um modelo para representar informações sobre recursos na web, utilizando URIs para identificar entidades e propriedades. É baseado em tripletas (sujeito-predicado-objeto) para expressar relações entre recursos e seus atributos.

Vocabulário controlado: um conjunto de termos pré-definidos e organizados de forma hierárquica ou categorizada, utilizado para garantir consistência na descrição semântica de recursos. O DCAT-BR recomenda o uso de vocabulários controlados para propriedades como dcat:theme e adms:status.

Vocabulário (RDF): um conjunto de termos (classes e propriedades) definidos em RDF para descrever recursos e suas relações. O DCAT-BR utiliza termos de diversos vocabulários RDF, como DCAT, DCTERMS, FOAF, entre outros.
